# manual_sql_audit

Версия файла: `261030.06`.

## Назначение

Модуль ведёт отдельный аудит ручных SQL-запросов, выполняемых через команду `/sql`.

`/sql` — это осознанный ручной доступ к БД, поэтому его вызовы хранятся отдельно:

- `audit.log` — общий журнал диалога;
- `security.log` — отказы и события безопасности;
- `logs/manual_sql.log` — только аудит ручных SQL-запросов.

Ограничения сложности SQL к `/sql` не применяются: модуль только журналирует и ничего не блокирует.

## Публичный API

### `get_manual_sql_logger() -> logging.Logger`

Возвращает логгер `manual_sql`, инициализированный ровно один раз.

Особенности:

- пишет в `logs/manual_sql.log`;
- использует `RotatingFileHandler`;
- параметры ротации берутся из env-переменных:
  - `LOG_MAX_BYTES` — по умолчанию `104857600`, минимум `1`;
  - `LOG_BACKUP_COUNT` — по умолчанию `5`, минимум `0`;
- formatter наследуется у логгера `audit`, затем у root, иначе используется стандартный формат;
- при повторной инициализации не добавляет дублирующий `RotatingFileHandler`;
- `propagate = False`, чтобы записи не уходили в общий лог;
- если файл лога открыть не удалось, пишется `WARNING`, а приложение продолжает работу без аудита `/sql`.

### `log_manual_sql(user_id: str, db_name: str | None, sql: str, duration_ms: float, rows_returned: int | None = None, error: str | None = None) -> None`

Пишет одну запись аудита ручного SQL в `logs/manual_sql.log` в формате JSON.

Аргументы:

- `user_id` — ID пользователя, выполнившего `/sql`;
- `db_name` — имя текущей БД;
- `sql` — полный текст запроса, не обрезается;
- `duration_ms` — длительность выполнения в миллисекундах;
- `rows_returned` — число строк при успехе;
- `error` — текст ошибки при неуспехе.

В запись добавляются:

- `timestamp`;
- `type = "manual_sql"`;
- `user_id`;
- `db_name`;
- `sql`;
- `duration_ms` с округлением до 3 знаков;
- `status = "success"` или `"error"`;
- `rows_returned` при успехе;
- `error` при ошибке.

Функция никогда не выбрасывает исключение: сбой аудита не должен ломать `/sql`.

## Внутренние помощники

- `_env_int(name, default, minimum=0)` — безопасно читает целое значение из env, при некорректном значении пишет `WARNING` и возвращает `default`.
- `_inherit_formatter()` — ищет готовый formatter у логгеров `audit` и root, иначе возвращает стандартный формат.

## Зависимости

Модуль использует только стандартную библиотеку Python:

- `json`;
- `logging`;
- `os`;
- `datetime`;
- `logging.handlers.RotatingFileHandler`.

Импортов других модулей проекта в файле нет.

Неявные зависимости:

- файловая система и каталог `logs`;
- env-переменные `LOG_MAX_BYTES`, `LOG_BACKUP_COUNT`;
- настройки formatter логгера `audit` или root, если они уже сконфигурированы.

## Использование в проекте

Модуль экспортирует:

- `get_manual_sql_logger`;
- `log_manual_sql`.

По контракту он предназначен для обработчика команды `/sql`: после выполнения ручного SQL вызывающий код должен записать событие через `log_manual_sql(...)` либо получить логгер через `get_manual_sql_logger()`.

Конкретные модули-вызывающие в этом файле не видны, так как импортов из проекта нет.

## Ротация и устойчивость

- Лог пишется через `RotatingFileHandler` в `logs/manual_sql.log`.
- Используются те же env-переменные ротации, что у `audit.log` и `security.log`.
- При проблемах с открытием файла лога модуль деградирует мягко: пишет `WARNING` и продолжает работу.
- Аудит `/sql` не должен приводить к падению бота из-за ошибок логирования.
