# `app/core/llm_client.py`

Версия файла: `261030.01`.

## Назначение

Модуль предоставляет класс `LLMClient` — асинхронную обёртку над `AsyncOpenAI` для работы с OpenAI-совместимыми LLM: локальными LM Studio/Ollama и удалёнными провайдерами.

Основные задачи модуля:
- загрузка конфигурации моделей из `config/models.yaml`;
- hot-reload конфига при изменении mtime;
- подстановка `${VAR}` из переменных окружения;
- выбор клиента и модели по имени;
- хранение лимитов контекста;
- выполнение `chat`-запросов с поддержкой `temperature`, `max_tokens`, `tools`, `tool_choice`, `response_format`;
- retry-fallback, если провайдер не поддерживает `tool_choice` или `tools`;
- корректное закрытие всех созданных клиентов.

## Ключевые изменения версии `261030.01`

- В `chat()` передача `max_tokens` стала строже: параметр добавляется только если значение не `None`, приводится к `int` и больше нуля.
- Некорректное значение `max_tokens`, которое не приводится к `int`, игнорируется с warning в лог.
- Неположительные значения `max_tokens` не передаются в API.

## Класс `LLMClient`

### `__init__(config_path="config/models.yaml", default_model="tool_calling_model")`

Создаёт экземпляр клиента.

Аргументы:
- `config_path` — путь к YAML-файлу с конфигурацией моделей;
- `default_model` — имя модели по умолчанию.

Внутри хранит:
- `config` — загруженный конфиг;
- `clients` — кэш `AsyncOpenAI`-клиентов по именам моделей;
- `_clients_meta` — метаданные клиентов для hot-reload;
- `_context_lengths` — лимиты контекста по моделям;
- `_mtime` — время последнего изменения конфига.

### `load_config(force=False) -> None`

Загружает `models.yaml`.

Аргументы:
- `force` — если `True`, перечитывает файл даже при неизменном mtime.

Особенности:
- проверяет mtime и выполняет hot-reload;
- подставляет значения вида `${VAR}` из окружения;
- при отсутствии переменной окружения пишет предупреждение и подставляет пустую строку;
- формирует `_context_lengths` из `context_length` или `DEFAULT_CONTEXT_LENGTH`;
- при ошибках чтения/парсинга YAML логирует проблему и оставляет пустой конфиг;
- если `config['models']` не является словарём, логирует ошибку и заменяет его на `{}`.

### `get_model_names() -> list[str]`

Возвращает список имён моделей из конфигурации. Перед чтением выполняет hot-reload. Если `models` не является словарём, возвращает пустой список.

### `resolve_model_name(short_name: str) -> str | None`

Разрешает сокращённое имя модели в полное имя из конфигурации.

Правила:
- сначала ищет точное совпадение без учёта регистра;
- затем ищет уникальное совпадение по префиксу `"<short_name>_"`;
- если префиксных совпадений несколько, возвращает `None`;
- если `short_name` пустой, возвращает `None`.

### `get_context_length(model_name: str | None = None) -> int`

Возвращает лимит контекста для модели.

Аргумент:
- `model_name` — имя модели; если не передано, используется `default_model`.

Если значение не найдено, возвращается `_DEFAULT_CONTEXT_LENGTH`, которое берётся из env `DEFAULT_CONTEXT_LENGTH` или равно `32768`.

### `_get_model_conf(name: str) -> dict`

Возвращает конфиг модели или пустой `dict`, если модель отсутствует или её конфиг не является словарём.

### `_make_client(name: str, model_conf: dict) -> AsyncOpenAI`

Создаёт `AsyncOpenAI` для модели.

Проверки:
- пустой `api_key` допустим для локальных моделей: `base_url` содержит `localhost`/`127.0.0.1` или `base_url` не задан;
- для удалённой модели с заданным `base_url` пустой ключ вызывает `ValueError`;
- если ключ непустой, проверяется, что он содержит только ASCII-символы;
- в клиент передаётся `base_url or None` и `api_key or "not-needed"`.

### `get_client(model_name: str | None = None) -> tuple[AsyncOpenAI, str, bool]`

Возвращает кортеж:
- `AsyncOpenAI`-клиент;
- фактическое имя модели для API;
- флаг `supports_tools`.

Аргумент:
- `model_name` — имя модели из конфига; если не передано, используется `default_model`.

Особенности:
- выполняет hot-reload конфига;
- если модель не найдена — выбрасывает `ValueError`;
- пересоздаёт клиент при изменении `base_url` или `api_key`;
- старый клиент закрывается через event loop, если он доступен; иначе закрытие оставляется на GC;
- фактическое имя модели берётся из `model_name` в конфиге модели или совпадает с именем модели в конфиге;
- `supports_tools` по умолчанию `False`.

### `async chat(messages, tools=None, model_name=None, tool_choice=None, response_format=None) -> dict`

Аргументы:
- `messages` — список сообщений в формате OpenAI;
- `tools` — список инструментов;
- `model_name` — имя модели из конфига;
- `tool_choice` — `"auto"`, `"required"` или `"none"`;
- `response_format` — например, `{"type": "json_object"}`.

Поведение:
- загружает конфиг и получает клиент через `get_client()`;
- `temperature` берётся из конфига модели, по умолчанию `0.0`; при ошибке преобразования используется `0.0`;
- `max_tokens` добавляется только если значение не `None`, приводится к `int` и больше нуля;
- если `max_tokens` не приводится к `int`, пишется warning, параметр не передаётся;
- если `max_tokens` равен нулю или отрицателен, параметр не передаётся;
- `tools` передаются только при `supports_tools=True` и непустом списке `tools`;
- если переданы `tools`, но `supports_tools=False`, пишется warning, инструменты игнорируются;
- `tool_choice` передаётся только для допустимых значений и при переданных `tools`;
- `response_format` передаётся, если не `None`;
- возвращает `response.model_dump()`.

Fallback-retry:
- при ошибке, связанной с `tool_choice`, повторяет запрос без `tool_choice`;
- при ошибке, связанной с `tools` или `tool`, повторяет запрос без `tools` и `tool_choice`;
- если fallback не помог, исключение пробрасывается дальше.

### `async close() -> None`

Закрывает все созданные клиенты.

Особенности:
- очищает `clients` и `_clients_meta`;
- ошибка закрытия одного клиента логируется и не блокирует закрытие остальных.

## Использование другими модулями проекта

В изолированном файле нет импортов других модулей проекта, поэтому конкретные места вызова по нему не видны. Модуль экспортирует публичный класс `LLMClient`, который другие части проекта могут импортировать, например:

`from app.core.llm_client import LLMClient`

Предполагаемые точки использования публичного API:
- создание `LLMClient` при инициализации приложения;
- `chat(...)` — основные запросы к LLM;
- `get_client(...)` — прямой доступ к `AsyncOpenAI`, если нужен нестандартный вызов;
- `get_model_names()`, `resolve_model_name(...)`, `get_context_length(...)` — команды `/model`, валидация и работа с контекстом;
- `close()` — завершение работы приложения.

## Особенности и ограничения

- Hot-reload выполняется по mtime; при неизменном mtime конфиг не перечитывается, если не передан `force=True`.
- `_clients_meta` фактически отслеживает `base_url` и `api_key`; `temperature` читается при каждом `chat()` и не требует пересоздания клиента.
- При отсутствии `${VAR}` в окружении подставляется пустая строка с warning.
- `supports_tools=False` означает, что переданные `tools` будут проигнорированы с предупреждением.
- `max_tokens` добавляется только при значении не `None` и `> 0`; нечисловое значение игнорируется с warning; неположительное значение просто не передаётся.
- `response_format` не валидируется модулем и передаётся в API как есть.
- Fallback в `chat()` делает повторный запрос только при признаках неподдержки `tool_choice` или `tools`; остальные ошибки пробрасываются.
- `temperature` настраивается в `models.yaml`; для `tool_calling_model` разумно `0.0`, для `analysis_model` — `0.2–0.3`.
- Внешняя документация не предоставлена; сохранённых дополнительных разделов нет.
