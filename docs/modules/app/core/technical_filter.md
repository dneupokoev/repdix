# app/core/technical_filter.py

## Назначение
Модуль определяет, является ли имя таблицы/схемы/колонки «техническим». Техническим считается имя, которое начинается с одного из заданных префиксов. По умолчанию используется префикс `technical_`. Проверка выполняется без учёта регистра.

Модуль поддерживает как короткие имена (`technical_logs`), так и fully-qualified имена (`schema.table`, `schema.table.column`): для qualified-имени техническим считается имя, у которого хотя бы одна часть, разделённая точками, начинается с технического префикса.

## Константы
- `DEFAULT_PREFIXES = ("technical_",)` — префиксы по умолчанию.
- `dv_file_version = '261029.05'` — служебная версия файла; в логике модуля не используется.

## Функции

### `get_technical_prefixes() -> tuple[str, ...]`
Читает префиксы из переменной окружения `TECHNICAL_PREFIXES`.

Поведение:
- если `TECHNICAL_PREFIXES` после `strip()` непустая, значение разбивается по запятым;
- каждая часть очищается от пробелов и приводится к нижнему регистру;
- пустые части отбрасываются;
- если переменная не задана или содержит только пробелы, возвращается `DEFAULT_PREFIXES`.

Особенность: если переменная задана, но после фильтрации не остаётся ни одного префикса, возвращается пустой кортеж. В этом случае проверки `is_technical()` и `is_technical_qualified()` будут возвращать `False`.

### `is_technical(name: str) -> bool`
Проверяет, начинается ли имя с одного из технических префиксов.

Аргументы:
- `name` — проверяемое имя.

Возвращает:
- `True`, если имя непустое и начинается с любого префикса из `get_technical_prefixes()`;
- `False` для пустого имени или если совпадений нет.

Проверка регистронезависимая. Префиксы читаются при каждом вызове.

### `is_technical_qualified(name: str) -> bool`
Проверяет fully-qualified имя (`schema.table`, `schema.table.column`).

Аргументы:
- `name` — проверяемое имя.

Возвращает:
- `True`, если хотя бы одна часть имени, разделённая точками, является технической по `is_technical()`;
- `False` для пустого имени.

Для короткого имени без точек поведение совпадает с `is_technical()`.

Примеры:
- `is_technical("technical_logs")` → `True`
- `is_technical_qualified("db.technical_logs")` → `True`
- `is_technical_qualified("public.users")` → `False`

## Зависимости
- `os` — чтение переменной окружения `TECHNICAL_PREFIXES`.
- `re` — импортирован, но в текущей реализации не используется.
- Локальные модули проекта не импортируются.

## Использование другими модулями
В предоставленном изолированном фрагменте нет информации о том, какие модули проекта импортируют или вызывают этот файл. Публичный API предназначен для вызовов `is_technical()` и `is_technical_qualified()` при фильтрации технических схем, таблиц и колонок.

## Ограничения и заметки
- Проверка выполняется только по началу строки, а не по полному совпадению имени.
- Регистр не учитывается.
- Префиксы не кешируются: `get_technical_prefixes()` читает переменную окружения при каждом вызове.
- Формат префиксов не валидируется; например, префикс без завершающего `_` будет совпадать с более широким набором имён.
- `import re` присутствует, но не используется.
