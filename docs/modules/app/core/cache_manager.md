# app/core/cache_manager.py

## Назначение

Асинхронный менеджер кэша на Redis для истории диалогов и схемы БД. Представляет собой обёртку над `redis.asyncio.Redis` с принципом graceful degradation: при ошибках Redis основные методы не бросают исключения, а возвращают безопасные значения, чтобы бот мог продолжать работать без кэша.

Версия файла: `261028.09`.

## Основной класс

### `CacheManager`

Обёртка над асинхронным клиентом Redis. Все методы, кроме `ping()`/`healthcheck()`, перехватывают ошибки Redis и логируют их через `logger.warning`.

#### Конструктор

```python
CacheManager(
    host: str = "localhost",
    port: int = 6379,
    db: int = 0,
    password: str | None = None,
    socket_timeout: float = 5.0,
    socket_connect_timeout: float = 5.0,
)
```

Аргументы:

- `host` — хост Redis, по умолчанию `localhost`.
- `port` — порт Redis, по умолчанию `6379`.
- `db` — номер БД Redis, по умолчанию `0`.
- `password` — пароль. Если `None` или пустая строка, аутентификация не используется.
- `socket_timeout` — таймаут чтения/записи, по умолчанию `5.0` сек.
- `socket_connect_timeout` — таймаут подключения, по умолчанию `5.0` сек.

Клиент создаётся с `decode_responses=True`, поэтому значения возвращаются как `str`, а не `bytes`. Также включён `retry_on_timeout=True`.

## Методы

- `async ping() -> bool` — проверяет доступность Redis через `PING`. Не бросает исключений: при ошибке логирует warning и возвращает `False`. Предназначен для fail-fast проверки при старте.
- `async healthcheck() -> bool` — алиас `ping()` для читаемости.
- `async get(key: str) -> str | None` — возвращает значение по ключу или `None`. При ошибке Redis возвращает `None`.
- `async set(key: str, value: str, ttl: int = 86400) -> bool` — сохраняет значение с TTL. Если `value is None`, запись пропускается и возвращается `False`. Пустая строка считается валидным значением. При ошибке возвращает `False`.
- `async delete(key: str) -> bool` — удаляет ключ. Возвращает `True`, если операция выполнена успешно, в том числе если ключа не было. При ошибке Redis возвращает `False`.
- `async mget(keys: list[str]) -> list[str | None]` — возвращает значения по списку ключей. Для пустого списка возвращает `[]`. При ошибке возвращает список `None` длиной `len(keys)`.
- `async mset(mapping: dict[str, str], ttl: int = 86400) -> bool` — сохраняет несколько ключей с одинаковым TTL через pipeline. Значения `None` пропускаются. Пустой словарь считается успешной операцией. При ошибке возвращает `False`.
- `async delete_pattern(pattern: str) -> int` — удаляет все ключи по шаблону через `SCAN`/`scan_iter`, а не через `KEYS`. Возвращает количество удалённых ключей. Для пустого шаблона возвращает `0`, при ошибке — `-1`.
- `async close() -> None` — закрывает соединение с Redis. Метод идемпотентен: повторный вызов ничего не делает. Сначала пытается вызвать `aclose()`, затем при необходимости использует fallback на `close()`.

## Поведение и ограничения

- Модуль рассчитан на асинхронное использование.
- Все методы, кроме `ping()`/`healthcheck()`, не пробрасывают исключения Redis наружу.
- `set()` не сохраняет `None`, но сохраняет пустую строку.
- `mget()` при ошибке возвращает список `None`, чтобы сохранить соответствие количеству запрошенных ключей.
- `mset()` использует pipeline с `transaction=False`; TTL задаётся одинаковым для всех ключей.
- `delete_pattern()` использует `SCAN`, что безопаснее для больших баз, чем `KEYS`.
- `close()` идемпотентен и поддерживает разные версии `redis-py`.
- Ошибки логируются через `logger.warning` с `%s`-форматированием.
- Закрытие соединения логируется на уровне `info`.

Внешние и стандартные зависимости:

- `redis.asyncio as redis` — асинхронный клиент Redis.

Импортов других модулей проекта в файле нет.

## Использование в проекте

По импортам внутри файла обратные зависимости проекта не видны. Из docstring и комментариев следует:

- `main.py` использует `ping()`/`healthcheck()` для fail-fast проверки доступности Redis при старте.
- `/clear` может использовать `delete_pattern()` для очистки ключей пользователя.
- История диалогов хранится в ключах вида `repdix:history:{user_id}` в виде JSON-строк; `engine` ожидает значения как `str`.
- Модуль также предназначен для работы со схемой БД и другими кэшируемыми данными.
