# 📘 Проект: repdix (Reporting & Data eXplorer)

## 🎯 1. Цель проекта
Создать универсального Telegram-бота-оркестратора, который принимает вопросы на естественном языке, переводит их в SQL-запросы через LLM, выполняет их в базе данных (MySQL, PostgreSQL, SQLite) и возвращает пользователю **глубокий аналитический ответ**. 

Бот работает в режиме **AI-агента**: он умеет самостоятельно строить цепочки SQL-запросов (Agent Loop), находить скрытые закономерности (например, «почему упали продажи»), показывать процесс своих рассуждений в реальном времени (Chain of Thought) и прерывать выполнение по команде.

## 🛠️ 2. Технологический стек
- **Язык:** Python 3.12.
- **Менеджер зависимостей:** Pipenv.
- **Асинхронность:** `asyncio`, `asyncio.Task` (для фоновых задач и отмены).
- **Telegram:** `aiogram` (v3.x).
- **LLM:** `openai` (AsyncOpenAI). Основная модель — **DeepSeek V4.1 Flash** (через OpenCode Zen) или локальные аналоги.
- **Базы данных:** `aiomysql` (MySQL), `asyncpg` (PostgreSQL), `aiosqlite` (SQLite).
- **Кэширование:** `redis.asyncio`.
- **Конфигурация:** `python-dotenv` и `PyYAML`.

## 🏗️ 3. Архитектура (Порты и Адаптеры)
Ядро ничего не знает о Telegram. Общение идёт через абстрактные интерфейсы.

```text
repdix/
├── app/
│   ├── main.py                 # точка входа
│   ├── core/                   # бизнес-логика (независима от мессенджера)
│   │   ├── engine.py           # ядро: Agent Loop, tool_calls, управление сессией
│   │   ├── session.py          # SessionState (история, lock, current_task)
│   │   ├── db_manager.py       # пулы соединений, безопасные запросы
│   │   ├── llm_client.py       # клиент LLM (temperature=0.3, tool_choice)
│   │   ├── cache_manager.py    # Redis (история диалогов)
│   │   └── validator.py        # SQL-валидатор (только SELECT)
│   └── interfaces/             # адаптеры мессенджеров
│       ├── base.py             # ChatMessage (с колбэком статуса), ChatResponse
│       ├── telegram_adapter.py # Telegram (aiogram), отправка статусов, /stop
│       └── cli_adapter.py      # Консольный интерфейс (отладка)
├── config/
│   ├── databases.yaml          # шаблоны подключений (${VAR} из .env)
│   ├── models.yaml             # шаблоны моделей
│   ├── relations.yaml          # описание связей (для JOIN)
│   ├── templates.yaml          # детерминированные шаблоны (топы/рейтинги)
│   ├── users.yaml              # белый список (опционально)
│   └── help.md                 # справка /help
├── tests/                      # pytest
├── .env                        # секреты (НЕ КОММИТИТЬ)
└── .gitignore
```

## 🗄️ 4. Работа с базами данных
- **Шаблоны в `config/databases.yaml`**: реальные значения подставляются из `.env` через `${VAR}`.
- **Read-only на уровне БД обязателен.** Валидатор SQL — лишь дополнительный барьер. SQLite поддерживает только валидатор (для отладки).
- **Таймауты:** `SQL_QUERY_TIMEOUT` (по умолчанию 15 секунд) прерывает тяжелые запросы на уровне БД.

## 🧠 5. Работа с моделями и AI-Агент

### 5.1. Agent Loop (Цикл агента)
Это главная фича проекта. Бот не просто переводит вопрос в один SQL-запрос. В `engine.py` реализован цикл `while step < max_steps` (до 5 шагов). Модель может:
1. Запросить список таблиц.
2. Изучить структуру нужных таблиц.
3. Сделать один запрос за текущий месяц, другой за прошлый.
4. Сравнить результаты и написать бизнес-вывод.

**Важно:** В цикле сообщения модели обязательно передаются с ролью `"tool"` и `tool_call_id`, иначе DeepSeek вернёт ошибку 400.

### 5.2. Chain of Thought (Прозрачность)
Перед каждым вызовом инструмента модель **обязана** написать краткое пояснение (например, *«Сейчас посмотрю структуру...»*). 
**Как это работает:**
- В `base.py` в `ChatMessage` добавлено поле `status_callback`.
- В `telegram_adapter.py` создается функция `send_status`, которая отправляет промежуточные сообщения.
- В `engine.py` текст модели перехватывается и отправляется через колбэк.
- Пользователь видит: `🤖 Сейчас выполню SQL-запрос...`

### 5.3. Инструменты модели (Tool Calling)
- `execute_sql` — для сложных аналитических запросов и `SHOW COLUMNS`.
- `get_relations` — узнать связи таблиц.
- `execute_template` — выполнить быстрый запрос из `config/templates.yaml` (для топ-5, кто работал).
- **⚠️ Важно:** Мы **отказались** от тяжелого `get_table_schema` (он возвращал гигантский JSON, переполнял контекст и ломал DeepSeek). Вместо этого в `base_prompt` модели велено использовать `SHOW COLUMNS FROM <table>` через `execute_sql`. **Не возвращайте `get_table_schema` обратно!**

### 5.4. Детерминированные шаблоны (`templates.yaml`)
Зачем нужны: LLM мощная, но иногда «ленится» делать простые агрегации. `execute_template` экономит токены. 
**Как обрабатываются периоды (важно):** В Python **нет** списков месяцев или парсинга дат. Модель передает период строкой (`period="этот месяц"`), а `_run_yaml_template` конвертирует её в SQL-функции (`CURDATE()`, `DATE_SUB`). Это убирает хардкод.

### 5.5. Управление историей и прерывание
- История хранится в `SessionState` и дублируется в Redis (TTL 24 часа, `max_history = 10`).
- **Как работает `/stop`:** В `telegram_adapter.py` обработка запускается в `asyncio.create_task`. Ссылка сохраняется в `SessionState.current_task`. Команда `/stop` вызывает `state.current_task.cancel()`, что прерывает все ожидания SQL и LLM.

## 🛠️ 6. Служебные команды
| Команда | Описание |
|---|---|
| `/stop` | **Прервать текущий анализ** (отменяет фоновую задачу). |
| `/help` | Справка. |
| `/db`, `/db <name>` | Текущая БД / выбор новой. |
| `/model`, `/model <name>` | Текущая модель / переключение. |
| `/sql <query>` | Выполнить SQL вручную. |
| `/history`, `/compact`, `/clear`, `/tokens` | Управление контекстом. |

## 🛡️ 7. Безопасность и UX
- **Асинхронность:** Бот не блокирует интерфейс. Запросы выполняются в фоне.
- **Защита от спама:** Если пользователь пишет новый вопрос во время анализа, бот предложит подождать или использовать `/stop`.
- **Защита от пустого ответа:** Если LLM вернёт пустоту, бот напишет `⚠️ Модель не смогла сформулировать ответ`.
- **Разбиение длинных сообщений:** Ответы > 4096 символов автоматически делятся на части.
- **Валидация:** `validator.py` пропускает только `SELECT`. Всё логируется в `logs/audit.log` (ротация 100 MB × 5).

## ⚙️ 8. Инструкция по настройке

### 8.1. Локальная разработка
1. Установите Python 3.12 и Pipenv.
2. `pipenv install --dev`.
3. Создайте `.env` и `config/*.yaml`.
4. Запустите Redis.
5. Запустите `./prj_start.sh`.

### 8.2. Файл `.env` (пример)
```env
# Telegram
TELEGRAM_TOKEN=ваш_токен
ALLOWED_USERS=123456789
ADAPTER=telegram

# LLM (DeepSeek)
LLM_TOOL_URL=https://opencode.ai/inference/openai/v1
LLM_TOOL_TOKEN=sk-ваш_ключ
LLM_TOOL_MODEL=deepseek-v4.1-flash
DEFAULT_MODEL=tool_calling_model

# Redis
REDIS_HOST=localhost
REDIS_PORT=6379

# Лимиты
SQL_QUERY_TIMEOUT=15
MAX_ROWS_IN_RESPONSE=100
MAX_MESSAGE_LENGTH=4000
```

## ⚠️ 9. Ограничения и известные проблемы
- **Одновременные запросы:** `asyncio.Lock` на каждого пользователя. Разные пользователи работают параллельно, один — последовательно.
- **Время ответа:** На сложный вопрос («почему упали продажи») бот может сделать 5–10 SQL-запросов и потратить 30–60 секунд. Используйте `/stop`, если передумали.
- **Стоимость LLM:** При использовании платных API (DeepSeek) сложный анализ может стоить несколько центов. Следите за балансом.
- **Схема БД:** Бот передаёт только список таблиц, а детали запрашивает через `SHOW COLUMNS`. Это экономит токены, но добавляет шаг.
